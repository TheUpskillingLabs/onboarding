# CLAUDE.md — onboarding-proto

## What this is

A responsive, click-through HTML prototype for **The Upskilling Labs** — a public, browse-first
member experience, the participant onboarding flow, the signed-in app (Discover · Dashboard ·
Profile), the embedded **Triangulator** sensemaking tool, and the **Poderator** (`moderator.html`)
and **Admin** (`admin.html`) persona surfaces reached through the avatar "View as" menu — plus
the **content directories** (`events/ library/ labs/`): real per-item pages generated by
`tools/generate.js` from each directory's `data.js` (see *Content directories + the generator*). No framework, no Tailwind, no app build
step, no backend. This prototype is the design source of truth for the production implementation
(see `docs/OLOS_BACKEND_CHANGES.md` for the backend plan it implies).

It is **mobile-first and fully responsive**: a phone-shaped experience on small screens
(bottom tab bar, full-screen steps, sticky CTAs) that expands into a real web app on desktop
(top nav, multi-column grids, centered auth sheets).

**Branch:** `claude/merge-repos-onboarding-proto-b3axjt` — push here.

> **Naming rule (hard):** the brand is **"The Upskilling Labs"**, shortened only to **"The Labs"** —
> never "TUL" or any other abbreviation. This applies to every user-facing string, label, title,
> and footer. (It's fine in prose/commits, never in rendered UI.)

> **Voice rule (hard, owner decision):** all user-facing copy is written in the Red Antler
> register at a smart-14-year-old reading level — short declarative sentences, plain words,
> second person, zero jargon ("things you've actually seen", never "field observations
> sensemaking"). Warm and human, but precise and confident: dates, numbers, and terms stated
> exactly; no hedging, no corporate speak, no cute-for-cute's-sake. Gravity moments (threshold,
> agreement, gate) stay weighty in plain language ("that's the deal, and you're agreeing to
> it"). **Always lead with the benefits, rooted in the member's hero's journey (owner
> decision):** the member is the hero and The Labs is the guide — copy opens with where THEY
> end up ("Thirteen weeks from now, you'll have built something real"), then the path, then
> the ask. Never open with what the program is or what it demands. **Never deprecate
> learning/education (owner decision):** the critique targets information overload and
> outdated methods, never learning itself — learning is always part of the story ("learning
> that becomes capability"). Reference lines already in the voice: "Find your people. Build
> your edge." / "Not a curriculum. Real work." / "You keep the craft, the credit, and the
> story."

## Design system

**Three layers, one source each (owner decision — "systemitize"):**
1. **`tokens.css`** — brand primitives + layout rhythm (`--pad`/`--maxw`, with the 1024px bump).
   Never re-declare them in a file's own `:root` (a per-file *override* like stories'
   narrower `--maxw` is fine — that's vocabulary, not re-declaration).
2. **`system.css`** — the shared components (see the repo-layout table). The home page is the
   reference design; every page inherits these rules, nobody copies them.
3. **Each file's `<style>`** — file-specific vocabulary only, layered last.

**Canonical brand palette**
(do not reintroduce the old `midnight`/`aqua` values):

| Token | Value | Use |
|---|---|---|
| `--ink` | `#00141B` | deepest navy — the logo background, nav bars, covers, footers |
| `--navy` | `#03232A` | primary brand navy |
| `--forest` | `#005F68` | deep teal-green, gradient endpoints |
| `--teal` | `#0094A0` | primary accent / CTAs / links |
| `--teal-deep` | `#007882` | hover / pressed / labels on light |
| `--red` | `#E11D2A` | high-priority CTAs (Create account, Register) and required markers only |
| `--paper` | `#F6F4EF` | **warm off-white — the only light page background** |
| `--white` | `#FFFFFF` | cards |
| `--charcoal` / `--slate` / `--meta` / `--meta-soft` | `#444` / `#4A5557` / `#748083` / `#A0ADB0` | text on light |
| `--od1/2/3` | `rgba(255,255,255,.95/.64/.40)` | text on dark |

Rules baked into the system:
- **One radius.** `--r: 14px` on every rectangular container — buttons included. No full pills.
  Genuine circles only (avatar, status dots, timeline pips, the orb, the Triangulator's modal-close).
- **Warm off-white only.** `--tint` (`#ECF3F4`) exists but is **not** used as a page background.
- **Light-first; dark is for "covers."** Dark `--ink`/gradient surfaces are reserved for the
  landing hero, the About hero, nav bars (logo always on navy), the ignition interstitial, and
  the open-source footer.
- **4px baseline grid.** Type line-heights and spacing are multiples of 4.
- **Type scale** classes: `.t-display .t-h1 .t-h2 .t-h3 .t-h4 .t-lede .t-body .t-small .lbl .idx .t-stat`.
- **Soft elevation:** `--shadow` / `--shadow-lg`; cards `.tappable` lift on hover (desktop only).
- **Grain:** `.grain` overlays an SVG-noise texture on dark surfaces.
- **The orb never sits raw under text or interactive elements** — at every breakpoint, put a
  scrim between the orb and content (see `.cycle-banner::after`) and/or cut its opacity on
  small screens. The orb's red lobe kills contrast under gray copy and next to red CTAs.
- **Mobile keyboard rules:** every input/textarea is `font-size:16px`+ (below 16px iOS zooms
  the page on focus); viewport metas carry `interactive-widget=resizes-content`; full-height
  shells use `100dvh` (not `svh`) so the keyboard shrinks them; focused flow inputs scroll
  into view.
- **App chrome switches at 768px** (top nav in, tabbar out, dashboard two-column) — the
  typography/padding scale-up stays at 1024px. Never leave a 640–1023px band on phone chrome.

Font: **Geologica** only (embedded base64 in `font.css` — no CDN, one fetch for the whole
suite). The Triangulator additionally
keeps its own functional/semantic colors (`--tier-1..6` ladder ramp, seven `--type-*` evidence
colors) — those are not brand palette and must stay recognizable.

## View architecture

**The signed-in app is real pages** — `dashboard/ my-cycle/ learning/ directory/ me/` — not a
SPA. `goApp(id)`/`showView(id)` treat destination changes as navigations (legacy panel ids
alias via `PANEL_ROUTES`); only ceremony views (`<div class="view">` inside `#screens`,
injected by `injectCeremonies()`) toggle in place on whatever page launched them. index.html
keeps its own local views for the landing + onboarding funnel.

### Signed-in navigation: Home · My Cycle · Learning · Directory · the avatar (Me)

The app bar (chrome.js `.appnav`) carries four destination links — **Home** (`dashboard/`),
**My Cycle** (`my-cycle/`), **Learning** (`learning/`), **Directory** (`directory/`) — plus
the **avatar as the fifth element**: "Me" is not a link but the avatar dropdown, whose first
item is a filled **Profile** button → `me/` (owner decision). Mobile: the bottom tab bar
carries the same five as real links (Home · Cycle · Learning · Directory · Me-avatar).
**Learning** = the full events + library catalogs + saved items. **Directory** = the member
directory (mentor-filterable chips), community updates, The Work teasers (projects · pods ·
people), and the city/metro search; a member card opens visitor mode in place at
`directory/?u={id}` (Directory stays lit — `closeMemberProfile()` returns to the list).
Every section renders from the data.js arrays (`EVENTS`, `RESOURCES`, `MEMBERS`, `METROS`)
so production swaps the data source, not markup.

**Cards are teasers; every content item has a real page (owner decision).** Events, library
resources, and metros render everywhere via the shared teaser helpers
(`eventTeaserHTML/resourceTeaserHTML/labTeaserHTML`) — real `<a>` links to the generated
`events/{slug}/`, `library/{slug}/`, `labs/{slug}/` pages (see *Content directories* below).
No accordion expansion on browse cards; buttons inside a link-card (hearts, waitlist join)
call `stopPropagation()` **and** `preventDefault()`. `panel-event`/`openEvent`/`initGallery`
are retired — event detail lives on the generated pages. The cycle page's working lists
(situations, proposals/ballot, team registration) keep `toggleExpand` accordions by design
(compare-and-vote works in place), and `stories.html` keeps its expand-in-place model.

Legacy panels (`panel-cycles/events/resources/bookmarks`) are retained as
"View all →" drill-ins only — no nav entries (panel-events/panel-resources now render teaser
grids from the data files). `panel-labs` graduated from drill-in to the
**metro search** destination: a free-text search over `METROS` (two states — `active` is DC
only, everything else is `waitlist`), with a **public twin on the landing** (`#sec-labs`
inline search — renders only once typing starts; both surfaces share `renderMetroList()`).
Join-a-waitlist and Start-a-waitlist are account-required but **city-first (owner decision)**:
anonymous visitors see the join modal / type their city *before* the account ask; the commit
tap stores `pendingWaitlist`/`pendingWaitlistCreate`, routes through `gateCreateAccount`, and
`consumePendingWaitlist()` auto-completes after signup — never ask for the city twice.
`userState.waitlists` (joined slugs, in-memory only — no localStorage); waitlist status
surfaces on the dashboard todos + profile cred band. Backend: `metros` +
`metro_waitlist_signups` (docs §1.1/§1.1b).

### Content directories + the generator (the mini-CMS)

**Production-architecture fidelity is the point (owner decision):** the repo's structure
mirrors OLOS's public surface as closely as a static host allows. The mapping:
`events/{slug}/` ↔ `/events/[slug]` route · `{type}/data.js` ↔ the DB table ·
`tools/generate.js` ↔ the server renderer · `olos.session.v1` ↔ the auth session ·
`index.html?join={slug}` / `?register=cycle` ↔ the authed waitlist/registration POSTs ·
`?view={panel}` ↔ the authed app routes. The About page (`about/`), the public Build Cycles
page (`cycles/`), and the Work layer (`projects/ pods/ people/` — public by artifact, private
by process: approved case studies, pod identity+output, opt-in portfolios) are generated the
same way. See docs/HANDOFF.md for the full translation map.

- **Editing content**: change the directory's `data.js`, run `node tools/generate.js`, commit
  both. Generated files carry a `<!-- GENERATED … -->` marker; the generator is idempotent and
  deletes orphaned generated pages (it can never touch `data.js` or hand-written files).
- **Every generated page ships**: canonical + OG meta, the global dark nav (auth-aware from the
  session flag), a breadcrumb, "more like this" recirculation, a signed-out upsell band, and
  the footer. Event pages carry a self-contained email-only RSVP modal; waitlist lab pages hand
  the join to the app via `index.html?join={slug}`; `labs/dc/` is the dark gravity cover.
- **Paths are relative, never leading-slash** (`../../tokens.css`) — GitHub Pages serves the
  repo from a subpath.
- Metros created at runtime (`createWaitlistMetro`) are in-memory only — they get a page when
  added to `labs/data.js` and the generator runs.

### Personas: one account, three lenses

Poderators and Admins register through the same path as everyone else. The avatar in the top
nav opens **`#avatar-menu`** (markup mirrored in all three pages; wiring in shared.js —
Esc/outside-click close, ArrowUp/Down cycle, `menuitemradio` semantics): Your profile · View
as **Upskiller / Poderator / Admin** (selected-dot on the current lens) · Sign out.
`viewAs(role)` persists `olos.viewAsRole.v1` and navigates; `moderator.html`/`admin.html`
boot-guards soft-redirect a stored `'upskiller'` lens back to `index.html` (click-through
convenience — real gating is server-side in OLOS). Both persona pages carry a dark nav,
persona pill, and "Exit to member view".

- **`admin.html`**: Testing Controls (the phase stepper — advancing into *tallied* runs the
  tally with the "✨ Naming projects…" beat and writes `olos.cycleState.v1` — plus the
  **Learning Log gate** toggle: arms/clears `logDueAt`, simulating the weekly cron), cycle
  status/windows/threshold knobs (live — the tally reads them), aggregate vote progress
  (never per-voter), invitations (role presets incl. Poderator, copyable links,
  Resend/Revoke), participants table + permissions modal, Entity Explorer disabled stub.
- **`moderator.html`** (rendered copy says **Poderator**, never "moderator"): framed as a
  **shepherd, not a manager** (owner decision) — members have wide latitude while making
  forward progress; the page unblocks and observes, never grades or assigns. Pod switcher
  (+ All-pods rollup), **frame-journey spine** (`renderJourney()` — five stages per pod,
  observations → situation → proposals → ballots → teams, each carrying its real artifact;
  phase-driven from `olos.cycleState.v1` via `applyFormationState()` at boot + `storage`
  event, so admin.html's Testing Controls light it up live), **Teams drill-down**
  (`renderTeams()` from `cycleState.projects`, attributed to pods via proposal titles —
  name, seats, frame, shepherd line, per-team "→ Process signal" prefill; empty state
  before the tally), phase/countdown/Learning-Log health band (`.status.watch`/
  `.status.risk`) + clarity/alignment averages + trend, needs-attention cards (blocked
  members first with their own "what do you need" text, then quiet loggers; mailto +
  "→ Process signal" prefill + session Dismiss; empty state), log-themes card (shared
  entries only), copy-to-clipboard AI bundle (no in-app LLM — matches OLOS), vote tallies,
  **Process signals** (`PROCESS_SIGNALS` + composer — where teams falter, the faltering is
  R&D data for upstream intervention design, never a member record; docs §6b),
  **weekly compliance strip** (`renderCompliance()` — logged vs waiting avatars per pod,
  due-Friday framing from `CYCLE_WEEK`; gated members get a red pip when `logDueAt` is
  armed — visibility, the gate does the enforcing), **member drawer** (`openMemberDrawer()`
  from roster rows — intake context + read-only practice + presence stubs; scoped edits are
  contact/pod only; "Flag as mentor material" → `MENTOR_FLAGS` → nominations pipeline),
  **Milestone Logs card** (`renderEvaluations()` — wk-7/13 status; evaluations are Learning
  Log variants `kind:'milestone_7'|'milestone_13'`, prefilled, never grades),
  **pod-scoped feedback inbox** (`POD_FEEDBACK`, read-only), orientation card (the A-vs-B
  answer: OLOS = practice record + formation pipeline; Luma = events; Slack = talk),
  staff/test accounts hidden by default (`visibleMembers()` + roster toggle — memo ask),
  filterable/sortable roster.

**Formation (mirrors OLOS's real pipeline) — never Discover content.** All on `panel-cycles`,
cycle-scoped, phase-driven from `olos.cycleState.v1` (`CYCLE.formationPhase`, read at boot +
via the `storage` event; admin.html's Testing Controls step it):
- **Problem Situations** (`SITUATIONS`, `renderCycleSituations()`, Month 1 · Problem Sprint):
  read-only history — the problem statements this cycle voted in, mapped in the Triangulator
  ("Voting closed" badge; no actions).
- **Solution Proposals → Projects** (`SOLUTION_PROPOSALS` → `CYCLE_PROJECTS`,
  `renderCycleFormation()` dispatching per phase): **submission** (one proposal per member,
  UPSERT via `FLOWS('solutionProposal')`, edit re-enters pre-filled) → **voting**
  (`renderSolutionBallot()`: budget ballot — submitters 5 / others 3 votes, threshold 5 to
  form; ballot locks through `#ballot-confirm`) → **tallied** (`tallyAndFormProjects()` +
  deterministic `generateProjectName()` — the "✨ naming" beat; OLOS does this with an LLM) →
  **registration** (`renderProjectRegistration()`: self-serve `registerForProject()`, one
  project per member, teams real at `projectMin` 3, cap `projectMax` 5 — reaching min fires
  the ignition interstitial). Gating helpers: `inCycle()` (membership) and `inProject()`.

**The cycle's public rhythm is the six anchor events** — Kickoff Summit + the five core
post-Kickoff events (Problem Sprint, Meet the Pods, Hackathon, Meet the Projects, Showcase
Summit). They lead the `EVENTS` array (`anchor:true`, `kind`), appear ✦-marked on the week
rail, drive `CYCLE.milestones`, and the five core events are the presence commitment in the
Open Cycle Agreement (rendered from the array — single source of truth). Phases are
`Problem Sprint / Frame Sprint / Building`.

**Cycles have modes (owner decision):** the noun is always **Build Cycle**; `CYCLE.mode`
is `'open'` or `'closed'`. Open Cycles publish everything to the commons (MIT code /
CC BY 4.0 content — pending legal review) and require the **Open Cycle Agreement**; the
commons term is whispered early (landing card + cycle-page lede), stated at the threshold,
bound at the signature — never sprung at signing.

**`panel-dashboard`** is the admin view of your own presence, in this order: **setup checklist
first** (actionable rows carry visible "Start →" buttons — no hover-only affordances; the
whole section collapses to a "Setup · All done ✓" strip once complete), then the **Practice
Log** (its own section), then dismissible "Up next" cards — the public composer is gone;
Learning Log shares are the primary source of member updates.

### Journey rules (added in the UX-improvements pass — keep these invariants)

- **Auth guard:** `App.boot` bounces signed-out visits to any app page back to `index.html`
  (production: middleware); the weekly Learning Log gate bounces every page but Home to
  `dashboard/` until the log is saved, and dims the nav (`body.log-locked`). All exits are auth-aware:
  the survey-share exit and the Triangulator chrome exit (`exitSurveyShare()` /
  `exitTriangulator()`) read "Back to dashboard / ← Back to Dashboard" for members and
  "Back to The Labs" for anonymous visitors (→ landing).
- **Trust is earned, never default:** `renderBadges(earned)` — fresh members see locked
  badges (`.badge-locked`, dashed, with how-to-earn tooltips); established mock members show
  the earned pills. Citation chips anchor inline after the claims they substantiate
  (`bioWithCitations`), falling back to end-of-bio for custom text.
- **Post-ignition continuity:** when your registration tips a team past `projectMin`, the
  ignition interstitial fires (with a "Later — back to your cycle" escape), the team card
  flips to "Open the project canvas", and a non-dismissible "Your project" card pins first
  in Dashboard "Up next". Casting a ballot always passes through the `#ballot-confirm`
  sheet (ballots lock once cast) — never mutate votes directly.
- **Concept before pool:** `triangulator.html`'s `pickInitialScreen()` routes a pre-seeded
  first-timer to the concept screen (the method needs a named concept for evidence to push
  against); the pool waits behind it. Mobile (<700px) gets a one-time "canvas works best on
  a larger screen" toast on entering the board.
- **Landing browses free:** no gated "See all" links; the cycle section carries the public
  situations strip (titles + "Brought by" only — UX F3) and the public license pair is always
  "MIT code · CC BY 4.0 content" (never CC BY-SA); section order is hero → **stories**

### Key user flows

- **Create account:** Landing → `view-google-auth` → `view-role-intent` → signup flow —
  **5 screens** (email · "Tell us who you are" `fields` step with first+last+zip on one
  screen · describes-you · hearAbout with the referral input inline via `step.followUp` ·
  consent). The lab is assigned silently from zip; there is no visibility step — profiles
  are members-only (`profileVisibility='labs'`, public tier deferred). Then role branches →
  gate-return (if the funnel was entered from a gated card) or dashboard.
- **Survey → Triangulator:** survey flow (`FLOWS('survey')`, loops via "add another") →
  observations append to `localStorage['olos.surveyPool.v1']` (seeded from `SURVEY_SEED`, the
  Civic & Elections CSV) → `view-survey-share` (copy `?survey=` link; the link deep-links
  straight into the flow, no account needed) → `openTriangulator()` → the iframe ingests the
  pool on boot and live via the `storage` event. **Prototype limit (by design):** single-browser
  aggregation only — real cross-user pooling is the OLOS `survey_responses` API.
- **Cycle registration has gravity (owner decision) — every seam gets a threshold:** flows
  never silently chain. Account creation is light; the cycle is the commitment. All four
  registration entries (post-signup role chain, cycles-page "Register", formation-note link,
  pod-chooser register-first) route through `startCycleRegistration(backFn, fromSignup)` →
  `view-cycle-threshold`, now **two beats (facilitator feedback): value before terms, terms
  before effort.** Beat 1 (`#ts1`) says what a cycle IS and what you get; `thresholdNext()`
  reveals beat 2 (`#ts2`): the three commitments in plain speech — five dated core events from
  `coreEvents()`, the weekly check-in named honestly (with the "just tell your Poderator —
  that's always okay" whisper — flexibility stays implicit, the all-events ask stands, owner
  decision), and the open-source term framed as **mutual freedom (owner wording)**: "the
  projects are open-source community projects — when the cycle's over you're free to do
  whatever you want with it, and so is everyone else." Never "nothing is your property";
  never "ships to the commons" in member-facing copy. "Not now" is a respectable exit on
  both beats. Then the registration questions (the old in-flow overview
  step was cut — beat 1 carries it) → the **Open Cycle Agreement** `signature` step (ceremony
  after intent: three commitments + typed full-name signature; Continue requires a full name;
  `finalLabel` "Sign & register"; `version:'open-2026-07-v2'` — softened wording, same
  substance). Signing writes `userState.cycleAgreement` `{name, at, version}`, flips
  `completed.cycle`, applies any `pendingPod`, and lands on `view-cycle-signed` (kickoff,
  `cycleICS()` calendar file, pod chooser). **Committed dates stay findable (facilitator user
  story):** `commitmentsHTML()`/`renderCycleCommitments()` render the dated anchor events +
  an anytime `.ics` link (`icsHref()`) on the cycle page (`#cycle-commitments-wrap`, members
  only) and in `renderDashCycle()`'s "Your commitments" rows (real dates, not week numbers).
  The agreement shows on the profile's Build Cycle credential and in the Poderator member
  drawer. Backend: `cycle_agreements` (docs §2c). The mentor explainer is the seam for
  mentors; the volunteer flow opens with a light info seam step.
- **Formation (cycle members only):** submit one solution proposal (flow UPSERT) → budget-
  vote on the ballot (locks on cast) → admin tallies (winners named, become `CYCLE_PROJECTS`)
  → self-register for exactly one team; at `projectMin` (3) registrations the team ignites →
  `view-team-ignition` → `view-project-canvas` (frame/intervention/metrics/evidence + a
  "Request a mentor" JIT-support block). Caps: 3 min · 5 max per team, `maxProjects` 4.
- **Learning Log (replaces the Practice Journal, and the Pulse before it):**
  `#learning-log-card` on the dashboard, one Save, three parts — (1) *Health check*: two 1–5
  sliders (clarity / pod alignment) + an "I'm currently blocked" toggle revealing "What do
  you need?"; explicitly private to the member's Poderator + admins. (2) *Scaffolded
  reflection*: three mad-libs prompts (figured out / exploring / next focus). (3) *Share
  preview*: live concatenated paragraph + a "Share to the Discover feed" toggle (writes
  `userState.updates`). Entries append to `userState.learningLogs` — unlimited logs; the
  form resets after save and recent logs list below with a count. Payload shape mirrors the
  backend `learning_logs` row (metrics / log_content / share_publicly — see docs §6).
  **The weekly cadence is a hard gate (owner decision):** admin.html's Testing Controls arm
  it by writing `logDueAt` into `olos.cycleState.v1` (the simulated weekly cron); while a
  cycle member has no log with `at >= logDueAt`, `logGateActive()` locks the app —

  `.gate-dim` dims everything but the Learning Log section, `#log-gate-banner` explains,

- **Evidence precedes assistance:** `FLOWS('mentorRequest')` — required tried/evidence/

- **Mentor pathways (self-service marketplace):** role-intent keeps Mentor (recruited mentors

## Flow engine

`view-flow` is data-driven; flows come from `FLOWS(name)` for
`'signup' | 'cycle' | 'mentor' | 'volunteer' | 'profile' | 'survey'`. Step types:
`info | text | textarea | choice | checks | tags | consent | signature`. Confirm-to-advance
everywhere; optional steps show Skip. The survey flow's `onComplete` loops back to the title
step when the user picks "add another" (resets `fstep`, calls `renderFlowStep()` directly).

> **Agreement rule (hard, owner decision):** ANY agreement — the Participant Agreement
> (signup `consent` step, `step.agreement`/`agreementTitle` render the full text), the Open
> Cycle Agreement (`signature` step), and every future one — is **scroll-gated** via
> `attachAgreeGate(scrollEl, hintEl, onRead)`: the agree/sign control stays inert until the
> reader scrolls the `.agree-scroll` box to its end (hint flips to "Read to the end ✓";
> content that fits without scrolling counts as read).

```js
startFlow(name, backFn)  renderFlowStep()  flowAdvance()  renderFlowInput(step)
```

## triangulator.html conventions

- Reskin only — the canvas/sorting/classify/export engine is untouched from upstream `triangles`.
  `cssToken()` reads colors from CSS variables, so token changes propagate to the canvas.
- Keep `--tier-*` / `--type-*` colors and the export subsystem's separate `SITE_STYLE_CSS`
  template as-is.
- `ingestSurveyPool()` runs at boot (before `pickInitialScreen()`) and on `storage` events —
  survey observations arrive tagged `'Survey Response'`.
- Never reset the iframe's `src` mid-session — the tool guards unsaved work with `beforeunload`.

## Conventions for future changes

- Keep the three regions (CSS / screens / JS) coherent in each file.
- Respect the design rules: warm `--paper` only, single `--r`, dark for covers/nav only,
  baseline grid, **"The Labs" / never "TUL"**.
- New listings reuse `.card` + `.media`; dense collections use `.cards.dense`; sparse use
  `.cards.two`. New Discover content belongs in the data arrays, not hand-written markup.
- Honor `prefers-reduced-motion` and keep keyboard focus states visible.
- Mock data shapes are contracts: keep `EVENTS` Luma-shaped (anchor events carry `kind` +
  `anchor:true`) and `RESOURCES` CMS-shaped (commons items carry `from` provenance) so the
  production data-source swap stays a swap (see `docs/OLOS_BACKEND_CHANGES.md`).
